# Decisions

| When | Decision | Why |
|---|---|---|
| 10 Nov | Build a Bifrost plugin, not a standalone checker app | Problem statement 06 needs both Tavily and Bifrost. As a plugin, every app behind the gateway gets checked with no code change, which also fits statement 04 (a Bifrost extension). |
| 11 Nov | Lead with the semantic cache, not just answer checking | Issue maximhq/bifrost#9748 already proposes a freshness-check plugin, but it does not touch the cache. Bifrost's cache expires entries by TTL only (`plugins/semanticcache/search.go`, lazy `expires_at` check; issue #2414), so a stale answer is replayed until the TTL runs out. |
| 11 Nov | A regex gate before any model call | Most answers have nothing that can go out of date. Skipping them costs zero tokens and zero searches, which matters for a check that runs on every response. |
| 11 Nov | The status is decided in Go, not by the model | The judge model's verdict only counts when its quote is found word for word in the source it cites. An ungrounded verdict falls back to "uncertain", so a hallucination can never evict a good answer. |
| 11 Nov | A model or search failure gives "unchecked", never "stale" | Fail safe toward serving: an outage of the checker must not wipe the cache. |
| 11 Nov | Judge calls go back through Bifrost itself | A `.so` plugin gets no Bifrost client, so the plugin calls the gateway's own `/v1/chat/completions`. That gives the checker Bifrost's fallbacks, retries, logs and budgets for free. A header marks these calls so the plugin skips them. |
| 11 Nov | Use the HTTP transport hooks | They run on cache hits as well as misses. The LLM post-hook does not run for plugins after a cache short-circuit, so it cannot see the answers that matter most. |
| 11 Nov | Evict with the cache's own `DELETE /api/cache/clear/{id}` | It is a public, documented endpoint, and the `cache_id` is already in `extra_fields.cache_debug`. No change to Bifrost is needed. |
| 11 Nov | Recheck windows per claim kind (prices 24h, versions 72h, leadership 7d) | A cache hit is re-verified only when its most volatile claim is due, so repeated hits do not each pay for a search. |
| 11 Nov | Add a `bestbefore/verify` virtual model | Statement 06 asks for a system that "accepts an LLM-generated answer". A virtual model keeps that inside the OpenAI-compatible API, with no new route or service. |
| 11 Nov | Build the gateway and plugin in one Dockerfile | The official image is statically linked and cannot load Go plugins, and a plugin must match the host's Go version, libc and dependency versions exactly. |
| 11 Nov | Skip the dashboard's TypeScript check in the image build | It only validates upstream's own source, and it stalled for over 25 minutes in a 4 GB Docker Desktop VM. |
| 11 Nov | Gemini 3.5 Flash-Lite as judge, falling back to 3.1 Flash-Lite and Gemma 4 26B | Gemini 2.5 Flash's free tier allows 20 requests a day per model (`GenerateRequestsPerDayPerProjectPerModel-FreeTier: 20`), and the first eval run used it up. Each model has its own quota, so a chain across models keeps the checker running. Flash-Lite models also answered in 1–3 s with JSON mode. `gemini-2.5-flash-lite` returned 404 for our key, so it is not in the chain. |
| 11 Nov | One provider retry, then fall back | A quota error does not clear on retry. With four retries each 429 cost about a minute before Bifrost moved to the fallback. |
| 11 Nov | Copy the gateway's `replace` directives into the plugin module | The plugin first failed to load: "plugin was built with a different version of package github.com/mark3labs/mcp-go/server". Bifrost replaces mcp-go with its own fork, and Go ignores replaces declared by dependencies, so `scripts/align-deps.sh` now copies them. |
| 11 Nov | Provider retries (4, backoff 1–10 s) and a 60 s checker budget | Gemini returned intermittent 503s. Bifrost's own retries absorb them, but with a 25 s budget the judge call timed out and the answer came back `unchecked`. |
| 11 Nov | Mock provider needs `allow_private_network` | Bifrost blocks providers on private IPs by default (SSRF protection), which includes the e2e mock's Docker network address. |
| 11 Nov | Match a contradiction's new value by words, and allow three-word quotes for contradictions | The first eval run rejected real contradictions: "Java 25" against a quote saying "JDK 25", and "Latest version: 19.3" for being under five words. It caught 65% of stale answers. The word-level rule still blocks every attack in `TestContradictionsThatProveNothingAreUncertain`, and the next run caught 80%. Both runs are published because the rule was tuned on the same set. |
| 11 Nov | Record why each verdict was rejected | To fix the rule we first had to see why verdicts were thrown out. `rejected_because` and `rejected_quote` now ship in every report, so users can audit decisions too. |
| 11 Nov | The eval stops after three failed checks in a row | A network drop mid-run turned ten answers into `unchecked`. That run was thrown away; the guard stops a spoiled run from being saved. |
| 11 Nov | Upgrade from a detector to a self-healing cache | Flagging and evicting a stale answer still left the next user to get the same stale answer from the model, and checking is a weak idea on its own. Correcting the answer before it is cached means every later user gets the fix from cache at cache speed. |
| 11 Nov | Heal in `PostLLMHook`, not in the HTTP hook | Bifrost sorts custom plugins after built-ins (`transports/bifrost-http/lib/config.go`, placement ranks) and runs post-hooks in reverse (`core/bifrost.go`, `RunPostLLMHooks`), so this hook runs before the semantic cache writes. Editing the response there changes what is cached. Proven end to end: the second ask is a cache hit with the corrected text. |
| 11 Nov | The model drafts the correction; Go accepts it | The rewrite must contain every verified new value and stay near the original's length, and Go appends the source URLs itself, so a rewrite cannot drop a fix, invent a citation or balloon. A rejected rewrite leaves the answer flagged and uncached. |
| 11 Nov | Skip the cache write for stale answers that could not be healed | Setting the cache's own `semantic_cache-no_store` context key from `PostLLMHook` keeps them out entirely, instead of writing and then evicting. |
| 11 Nov | Background sweeper on best-before dates | A TTL treats every answer alike. Re-checking each entry when its most volatile claim is due catches answers that went stale while cached, before a user asks. Eviction is all it can do, because a plugin cannot insert cache entries. |
| 11 Nov | Status and sweep as virtual models | They stay inside the OpenAI-compatible API, like `bestbefore/verify`, so no new route or service is needed and the demo page's dashboard reads them directly. |
| 11 Nov | The rewrite gets its own time budget | Live, a slow check used most of the shared 60 s and the rewrite timed out. Separate budgets fixed it without raising either. |
| 12 Nov | Check only answers headed for the cache by default (`check_scope`) | The check adds seconds. Answers that are cached are replayed to every later user, so that is where the check pays off; uncached answers now pass with no delay. `check_scope: "all"` keeps the old behaviour. |
| 12 Nov | Revalidate expired cache hits in the background by default | Re-checking a hit inline made a cache hit as slow as a model call. Serving it at once and re-checking behind the scenes is HTTP's stale-while-revalidate; the sweeper usually re-checks entries before their date passes anyway. `revalidate: "inline"` keeps the strict behaviour. |
| 12 Nov | One re-check per cache entry at a time | The sweeper and background revalidation share one in-flight set, so a burst of hits on one expired entry pays for a single check. This closes the "no request coalescing" limit. |
| 12 Nov | Check streams on the final chunk and append a correction | Two other projects in this hackathon handle streams; ours did not. Streamed text cannot be recalled, so a stale stream gets a correction delta and the cache's `no_store` switch keeps it out of the cache. |
| 12 Nov | Search the claim's official site too, and prefer it | Our final eval accepted "Gemini 1.5 Pro is Google's most capable model" from a page about the "1.5 family". A second Tavily search restricted to the publisher's domain, with the judge told to prefer it, targets exactly that error. |
| 12 Nov | CI runs the Go tests and the full end-to-end suite; CI publishes the image | Judges can see every push tested against a real Bifrost, and run the project with `docker compose pull` instead of a 15–30 minute source build. |
